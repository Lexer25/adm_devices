# adm_devices - модуль для управления устройствами

Версия модуля — константа `DEVICES_VERSION` в `init.php`.

## Документация (userguide)

Модуль зарегистрирован в справке Kohana (`config/userguide.php`), страницы лежат
в `guide/devices/`. Ссылка на справку появляется в шапке модуля (значок вопроса)
и ведёт на `guide/devices`.

| Адрес справки | Содержание |
| --- | --- |
| `guide/devices` | Назначение модуля, страницы модуля, требования |
| `guide/devices/groups` | Управление группами точек прохода из браузера: команды, способы выбора точек прохода, результат, сообщения |
| `guide/devices/cli` | Настройка CLI (Minion): задача `devices:door`, опции, проверка связи с ТС, коды возврата, типовые ошибки |
| `guide/devices/scheduler` | Постановка задачи в планировщик Windows (`schtasks` и графический интерфейс) |

Иллюстрации (если понадобятся) кладутся в `media/guide/devices/` и вставляются
в страницу как `![Описание](имя_файла.png)`.

| URL | Действие контроллера | Назначение |

## Управление группами точек прохода (`devices/groups`)

Страница выполняет команду управления сразу для набора точек прохода.

### Команды

| Код команды | Действие |
| --- | --- |
| `opendoor` | Открыть 1 раз |
| `lockdoor` | Закрыть навсегда |
| `opendooralways` | Открыть навсегда |
| `unlockdoor` | Разблокировать |

Код команды передаётся в `Model_Device::unlock_door_arr()`, который формирует
команду контроллеру в виде `<команда> Door=<ID_READER>`.

### Входные параметры (POST)

| Параметр | Назначение |
| --- | --- |
| `command` | код команды (см. таблицу выше); проверяется по «белому» списку |
| `id_dev[]` | перечень точек прохода — флажки в списке (ID_DEV) |
| `group_ids[]` | группы устройств (таблица `DEVGROUP`); раскрываются в точки прохода вместе с вложенными группами. Пустые группы в списке видны, но их флажок отключён |
| `id_dev_text` | набор точек прохода строкой, например `12, 15, 17` |
| `csrf_token` | токен `Security::token()` (защита от CSRF) |

Все три способа задания набора (флажки точек прохода, группы, строка ID_DEV)
объединяются. Перед выполнением команды список проверяется методом
`Model_Devicem::filter_access_points()`: команда выполняется только для
существующих точек прохода (`DEVICE.ID_READER IS NOT NULL`) — контроллеры,
серверы и несуществующие ID_DEV отбрасываются.

### Поведение

* Страница доступна только администратору (`Auth::instance()->logged_in('admin')`),
  иначе — редирект на `errorpage`.
* После выполнения команды выдерживается пауза 2 секунды и опрашивается новое
  состояние точек прохода (`Model_Device::getStatForOneController()`), как в
  разделе «Контроллеры».
* Результат показывается после редиректа (Post/Redirect/Get), поэтому обновление
  страницы не повторяет команду. Журнал выполнения хранится в сессии в ключе
  `devices_group_result`.

## Запуск команды одной строкой (Minion)

Задача `devices:door` (класс `Task_Devices_Door`,
файл `classes/Task/Devices/Door.php`) делает то же, что страница `devices/groups`:

```
c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --list=1
c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=opendoor --id_dev=483,484
c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=lockdoor --group=2
c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=unlockdoor --group=2 --test=1
```

Перечень ID_DEV **нельзя разрывать пробелом**: `--id_dev=483, 484` — это уже два
аргумента (Minion отдаёт второй как аргумент без имени). Задача отнесёт его к
списку ID_DEV и предупредит, но надёжнее писать `--id_dev=483,484` или
`--id_dev="483, 484"`.

Готовые примеры — в `devices_door_task.bat` (по умолчанию выполняет только
безопасный `--list=1`, остальные строки закомментированы).

| Опция | Назначение |
| --- | --- |
| `--command` | код команды: `opendoor`, `lockdoor`, `opendooralways`, `unlockdoor` (обязательна, кроме `--list=1`) |
| `--id_dev` | перечень точек прохода: `483,484 508;512` |
| `--group` | группы устройств: ID (`2,3`) или название (`"зона входа"`); вложенные группы раскрываются |
| `--test` | `1` — только показать, что будет затронуто; команды не отправляются |
| `--list` | `1` — показать группы устройств с числом точек прохода и выйти |
| `--force` | `1` — отправить команду даже при недоступном ТС-сервере |
| `--encoding` | `auto` (по умолчанию), `utf8`, `cp866`, `cp1251` — кодировка вывода в консоль |

Особенности:

* набор точек прохода складывается из `--id_dev` и `--group`; как и на странице,
  выполняется только для существующих точек прохода (`ID_READER IS NOT NULL`);
  ID, не являющиеся точками прохода, перечисляются в отчёте («Пропущены…»);
* служебная группа `ID_DEVGROUP = 1` («все устройства») не принимается — это защита
  от случайной команды всем точкам прохода;
* перед отправкой проверяется связь с транспортными серверами (`ip:порт` из таблицы
  `SERVER`, таймаут 3 с). При недоступном ТС команда не отправляется, в консоль
  выводится причина (таймаут, порт закрыт, не задан адрес и т. п.). Это важно потому,
  что `Model_Device::sendCommand()` при неудачном подключении вызывает `HTTP::redirect()`,
  что в консоли выглядит как `HTTP_Exception_302` без пояснений;
* само выполнение обёрнуто в try/catch: вместо необработанного исключения выводится
  понятное сообщение и код возврата `1`;
* в режиме `--test=1` обращения к оборудованию не происходит вообще (проверка связи
  при этом выполняется — она безопасна);
* вывод перекодируется в кодовую страницу консоли (определяется через `chcp`),
  поэтому русский текст читается и в CP866, и в CP1251, и в UTF-8;
* коды возврата: `0` — команда выполнена (или тестовый прогон), `1` — ошибка
  входных данных или недоступный ТС; каждое выполнение пишется в лог приложения (NOTICE).

## Модель `Model_Devicem`

Методы для страницы `devices/groups`:

* `get_access_points()` — все точки прохода с контроллером и транспортным сервером;
* `get_access_points_by_ids($ids)` — данные точек прохода по списку ID_DEV;
* `filter_access_points($ids)` — оставляет только существующие точки прохода;
* `get_device_groups()` — дерево групп устройств в том же составе, что и в разделе
  «Группы устройств» (`devgroup`): плоский список в порядке обхода, с уровнем
  вложенности, полным путём и количеством точек прохода. Группы без точек прохода
  тоже попадают в список (у них `total = 0`) — в представлении они показаны, но
  выбрать их нельзя;
* `get_group_access_point_ids($group_ids)` — точки прохода выбранных групп
  с учётом вложенных групп (защита от зацикливания иерархии).

Структура таблицы `DEVGROUP`: строки с `ID_DEV IS NULL` описывают группу
(`ID_DEVGROUP`, `NAME`, `ID_PARENT`), строки с `ID_DEV IS NOT NULL` —
принадлежность устройства группе (при этом `ID_PARENT` равен идентификатору
группы). Служебная корневая группа `ID_DEVGROUP = 1` в списках не показывается.
