# Настройка CLI (Minion) {#devices-cli}

## Что такое Minion и что нужно для запуска {#devices-cli-requirements}

**Minion** — это штатный «запускатель задач» фреймворка Kohana, который
используется в проекте. Задача модуля `devices` называется **`devices:door`**
и выполняет ровно те же команды, что и страница
[«Группы точек прохода»](groups), но запускается одной строкой из командной
строки — то есть её можно поставить в расписание
([планировщик Windows](scheduler)).

Для запуска нужны:

- PHP из комплекта XAMPP: `c:\xampp\php\php.exe`;
- запускающий скрипт Minion: `c:\xampp\htdocs\city\modules\minion\minion`;
- включённые модули `minion`, `devices`, `devgroup` (см. `application/bootstrap.php`);
- доступ к базе СКУД через подключение `fb` (DSN `ilove`) — **под тем же
  пользователем Windows**, под которым работает веб-приложение (см. раздел
  [«Планировщик Windows»](scheduler));
- право на запись в каталог `application/cache` — Minion стартует через
  `index.php`, а Kohana проверяет этот каталог при инициализации.

[!!] Если при запуске появляется сообщение
`Directory APPPATH\cache must be writable`, значит у пользователя, из-под
которого запускается php.exe, нет прав на запись в `application/cache`.
Это особенность окружения, а не задачи: выдайте права на каталог (или
запускайте от имени того же пользователя, под которым работает Apache).

## Проверка, что CLI работает {#devices-cli-check}

Список доступных задач:

    c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=help

Встроенная справка по задаче (выводится её описание и все опции):

    c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --help

## Задача devices:door {#devices-cli-task}

| Что | Значение |
| --- | --- |
| Имя задачи | `devices:door` |
| Класс | `Task_Devices_Door` |
| Файл | `modules/devices/classes/Task/Devices/Door.php` |
| Команды | `opendoor`, `lockdoor`, `opendooralways`, `unlockdoor` |
| Что использует | `Model_Devicem` (группы и точки прохода) и `Model_Device` (отправка команд контроллерам) |

Общий вид запуска:

    c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=КОМАНДА [--id_dev=СПИСОК] [--group=СПИСОК] [опции]

## Быстрый старт {#devices-cli-quickstart}

Показать группы устройств и количество точек прохода в них (только чтение):

    c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --list=1

Проверить, что будет затронуто, **ничего не отправляя** (тестовый прогон):

    c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=opendoor --id_dev=483 --test=1

Выполнить команду для перечня точек прохода:

    c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=opendoor --id_dev=483,484

Выполнить команду для группы устройств (со всеми вложенными группами):

    c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=unlockdoor --group=2

Пример вывода задачи `--list=1` (дерево групп, вложенные группы — с отступом):

    === Группы устройств (DEVGROUP) ===
    ГРУППА                                  ID      ТОЧЕК ПРОХОДА
    10 ВП тротуар ВП.                       862     8 (в самой группе: 0)
        Enter                               864     4
        Exit                                866     4
    ...
    зона входа                              2       82
    зона выхода                             3       42

    Выбрать группу: --group=ID (можно несколько через запятую) или --group="название"

## Опции {#devices-cli-options}

| Опция | Значение | По умолчанию |
| --- | --- | --- |
| `--command` | Код команды: `opendoor`, `lockdoor`, `opendooralways`, `unlockdoor`. Обязательна (кроме `--list=1`) | — |
| `--id_dev` | Перечень точек прохода: `483,484 508;512` | — |
| `--group` | Группы устройств: ID (`2,3`) или название (`"зона входа"`); вложенные группы раскрываются | — |
| `--test` | `1` — тестовый прогон: показать список и проверить связь с ТС, команды не отправлять | `0` |
| `--list` | `1` — показать группы устройств с количеством точек прохода и выйти | `0` |
| `--force` | `1` — отправить команду даже при недоступном ТС-сервере | `0` |
| `--encoding` | Кодировка вывода в консоль: `auto`, `utf8`, `cp866`, `cp1251` | `auto` |

## Как задать набор точек прохода {#devices-cli-targets}

Набор складывается из `--id_dev` и `--group` (как и на странице
`devices/groups`). Выполняется команда только для существующих точек прохода:
контроллеры, серверы и несуществующие идентификаторы отбрасываются, а их список
выводится в отчёте строкой **«Пропущены (не точки прохода)»**.

Группы задаются идентификатором (надёжнее всего) или названием:

    --group=2
    --group=2,3,377
    --group="зона входа"

[!!] Перечень `ID_DEV` **нельзя разрывать пробелом**: `--id_dev=483, 484` —
это уже два аргумента командной строки. Задача отнесёт второй аргумент к списку
`ID_DEV` и предупредит об этом, но правильнее писать `--id_dev=483,484` или
`--id_dev="483, 484"`.

Служебная группа `ID_DEVGROUP = 1` («все устройства») **не принимается** — это
защита от случайной команды сразу всем точкам прохода.

## Проверка связи с транспортным сервером {#devices-cli-ts}

Перед отправкой команды задача проверяет TCP-соединение с каждым транспортным
сервером (`ip:порт` из таблицы `SERVER`), через который работают выбранные точки
прохода. Таймаут — 3 секунды.

Пример вывода (формат):

    Транспортные серверы:
      ТС2 17 стр на .95 — 192.168.0.95:1967 (точек прохода: 12): связь есть

Если ТС недоступен, команда **не отправляется вообще** (никакой частичной
отправки), а в консоль выводится причина:

    Транспортные серверы:
      ТС1 — 192.168.0.134:1967 (точек прохода: 1): НЕТ СВЯЗИ — таймаут соединения (3 с) — сервер не отвечает

    ОШИБКА: команда не отправлена: нет связи с транспортным сервером (192.168.0.134:1967).
    Проверьте ТС-сервер и его доступность. Отправить всё равно: --force=1.

Возможные причины в сообщении: таймаут соединения (сервер не отвечает), порт
закрыт, узел/сеть недоступны, в настройках ТС не задан адрес или порт.

[!!] Проверка сделана потому, что `Model_Device::sendCommand()` при неудачном
подключении к ТС выполняет `HTTP::redirect()` — в браузере это переход на
страницу ошибки, а в консоли выглядело бы как `HTTP_Exception_302` без
пояснений. Теперь вместо этого выводится понятное сообщение, а само выполнение
обёрнуто в обработку исключений.

## Коды возврата и журнал {#devices-cli-exit}

| Код | Когда |
| --- | --- |
| `0` | Команда выполнена; тестовый прогон (`--test=1`) или список групп (`--list=1`) |
| `1` | Ошибка входных данных (не задана команда, неизвестная команда, пустой набор, группа не найдена, служебная группа), недоступен ТС-сервер, либо исключение при отправке |

Каждое выполнение команды записывается в лог приложения
(`application/logs/<год>/<месяц>/<день>.php`, уровень NOTICE): команда, количество
точек прохода и список `ID_DEV`.

## Кодировка вывода {#devices-cli-encoding}

Файлы модуля — в UTF-8, а консоль Windows обычно работает в CP866 или CP1251,
поэтому задача сама перекодирует вывод в кодовую страницу консоли (определяется
командой `chcp`). Если вывод выглядит «кракозябрами», укажите кодировку явно:

    --encoding=cp866
    --encoding=cp1251
    --encoding=utf8

Тот же параметр влияет на разбор названий групп, переданных в `--group`
(название приходит в консольной кодировке). Для ID групп это не важно.

## BAT-файлы {#devices-cli-bat}

В модуле есть два готовых BAT-файла:

| Файл | Назначение |
| --- | --- |
| `modules/devices/devices_door_task.bat` | Примеры для ручного запуска. По умолчанию выполняет только безопасный `--list=1`, остальные строки закомментированы |
| `modules/devices/devices_door_run.bat` | Обёртка для планировщика: принимает те же параметры, что и задача, пишет вывод в файл `door_task.log` рядом с собой и возвращает код возврата задачи |

Пример запуска через обёртку:

    modules\devices\devices_door_run.bat --command=lockdoor --group=2

## Типовые ошибки {#devices-cli-troubles}

| Сообщение | Причина и что делать |
| --- | --- |
| `ОШИБКА: не задана команда` | Не передан `--command`. Список команд — в разделе [«Команды»](groups#devices-groups-commands) |
| `ОШИБКА: неизвестная команда "…"` | Опечатка в коде команды |
| `ОШИБКА: не задан набор точек прохода` | Не переданы ни `--id_dev`, ни `--group` |
| `Пропущены (не точки прохода): …` | Указанные `ID_DEV` не являются точками прохода (например, это ID контроллера) — проверьте идентификаторы по странице `devices` |
| `ОШИБКА: группа с ID … не найдена` | Неверный ID группы — посмотрите список: `--list=1` |
| `ОШИБКА: группа 1 — служебная («все устройства»)` | Укажите конкретные группы вместо корневой |
| `НЕТ СВЯЗИ — таймаут соединения` | ТС-сервер недоступен с машины приложения: проверьте питание, сеть и адрес/порт в разделе «Настройка → ТС» |
| `HTTP_Exception_302` (в старых версиях) | Необработанный редирект `sendCommand()` при недоступном ТС. В текущей версии задачи заменён понятным сообщением и кодом возврата `1` |
| `Directory APPPATH\cache must be writable` | У пользователя нет прав на запись в `application/cache` (см. начало раздела) |
