# Задача в планировщике Windows {#devices-scheduler}

## Когда это нужно {#devices-scheduler-purpose}

Minion-задачу [`devices:door`](cli) удобно запускать по расписанию. Типовые
сценарии для групп точек прохода:

- утром **разблокировать** входную группу (`--command=unlockdoor --group=2`);
- вечером **закрыть** группу (`--command=lockdoor --group=2`);
- открыть группу на время разового мероприятия
  (`--command=opendooralways` … и отдельной задачей `--command=lockdoor` после
  его окончания).

[!!] Помните, что «Открыть навсегда» и «Закрыть навсегда» — это **режимы**:
они действуют до следующей команды. Если ставить их в расписание, ставьте парные
задачи (открыть утром — закрыть вечером), иначе точка прохода останется в
выбранном режиме навсегда.

## Подготовка {#devices-scheduler-prepare}

1. Узнайте ID нужной группы:

       c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --list=1

2. Сделайте тестовый прогон — он показывает список точек прохода и проверяет
   связь с транспортным сервером, ничего не отправляя:

       c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=lockdoor --group=2 --test=1

   Если в выводе `НЕТ СВЯЗИ` — сначала разберитесь с ТС-сервером: по расписанию
   команда тоже не дойдёт.

3. Проверьте, что задача работает вручную (без `--test=1`) и возвращает код `0`:

       c:\xampp\php\php.exe c:\xampp\htdocs\city\modules\minion\minion --task=devices:door --command=lockdoor --group=2
       echo %ERRORLEVEL%

4. Подготовьте BAT-обёртку (см. ниже) — планировщику удобнее указывать один
   файл, а весь вывод при этом попадает в лог.

## BAT-обёртка для планировщика {#devices-scheduler-bat}

В модуле уже есть готовая обёртка — `modules/devices/devices_door_run.bat`:

    @echo off
    rem Обёртка для планировщика Windows: все аргументы передаются задаче devices:door,
    rem вывод дописывается в door_task.log рядом с этим файлом.
    setlocal
    set "PHP=c:\xampp\php\php.exe"
    set "MINION=c:\xampp\htdocs\city\modules\minion\minion"
    set "LOG=%~dp0door_task.log"
    "%PHP%" "%MINION%" --task=devices:door %* --encoding=cp1251 >> "%LOG%" 2>&1
    exit /b %ERRORLEVEL%

Планировщик вызывает её так:

    c:\xampp\htdocs\city\modules\devices\devices_door_run.bat --command=lockdoor --group=2

Код возврата задачи (`0` — успех, `1` — ошибка) обёртка передаёт планировщику
без изменений, поэтому в планировщике видно «Результат последнего запуска»:
`0x0` — успех, `0x1` — ошибка.

## Вариант 1. Командная строка (schtasks) {#devices-scheduler-schtasks}

[!!] Задачу должен создавать администратор, а запускаться она должна **под той
же учётной записью Windows**, под которой работает веб-приложение: подключение
к базе СКУД (`DSN ilove`) обычно определено в пользовательском разделе реестра
(`HKEY_CURRENT_USER`), поэтому под другой учётной записью (например, `SYSTEM`)
Minion может подключиться к другой базе или не подключиться вовсе.

Своё имя учётной записи можно узнать командой `whoami` (например,
`honor\андрей`).

Открыть группу утром в 08:00 (ежедневно):

    schtasks /Create /TN "Artonit City: открыть зону входа" ^
        /TR "c:\xampp\htdocs\city\modules\devices\devices_door_run.bat --command=unlockdoor --group=2" ^
        /SC DAILY /ST 08:00 /RU "honor\андрей" /RP * /RL HIGHEST /F

Закрыть группу вечером в 22:00:

    schtasks /Create /TN "Artonit City: закрыть зону входа" ^
        /TR "c:\xampp\htdocs\city\modules\devices\devices_door_run.bat --command=lockdoor --group=2" ^
        /SC DAILY /ST 22:00 /RU "honor\андрей" /RP * /RL HIGHEST /F

Пояснения к ключам:

| Ключ | Значение |
| --- | --- |
| `/TN` | Имя задачи в планировщике |
| `/TR` | Что запускать: BAT-обёртка и её аргументы |
| `/SC DAILY` `/ST 08:00` | Ежедневно в указанное время (можно `ONCE`, `WEEKLY`, `MINUTE` и др.) |
| `/RU` | Учётная запись, под которой выполняется задача |
| `/RP *` | Запрос пароля этой учётной записи (пароль вводится в консоли и хранится планировщиком). Чтобы не вводить пароль, создайте задачу в графическом интерфейсе с режимом «Выполнять только когда пользователь вошёл в систему» |
| `/RL HIGHEST` | Запуск с наивысшими правами |
| `/F` | Перезаписать задачу с таким именем, если она уже есть |

Проверка и управление:

    rem список свойств задачи, включая результат последнего запуска
    schtasks /Query /TN "Artonit City: открыть зону входа" /V /FO LIST

    rem выполнить прямо сейчас (проверка, что расписание настроено верно)
    schtasks /Run /TN "Artonit City: открыть зону входа"

    rem удалить задачу
    schtasks /Delete /TN "Artonit City: открыть зону входа" /F

## Вариант 2. Графический планировщик {#devices-scheduler-gui}

1. Откройте **Планировщик заданий**: `Win+R` → `taskschd.msc`.
2. **«Создать задачу»** (не «Простую задачу» — в обычной задаче больше нужных
   настроек).
3. Вкладка **«Общие»**:
   - имя, например `Artonit City: закрыть зону входа`;
   - **«Выполнять только когда пользователь вошёл в систему»** — если не хотите
     хранить пароль; либо **«Выполнять независимо от того, вошёл ли пользователь
     в систему»** — тогда потребуется пароль учётной записи;
   - учётная запись — та же, под которой работает приложение (не `SYSTEM`);
   - флажок **«Выполнять с наивысшими правами»**.
4. Вкладка **«Триггеры»** → «Создать»: «По расписанию», ежедневно, время
   (например, `22:00`).
5. Вкладка **«Действия»** → «Создать»: действие **«Запуск программы»**;
   - программа: `c:\xampp\htdocs\city\modules\devices\devices_door_run.bat`
   - аргументы: `--command=lockdoor --group=2`
   - рабочий каталог: `c:\xampp\htdocs\city\modules\devices`
6. Вкладка **«Условия»**: снимите лишние ограничения (например, «Запускать
   только при питании от сети», если это стационарный компьютер).
7. Вкладка **«Параметры»**: «Выполнять задачу по требованию» — можно оставить;
   «Перезапускать при сбое» — по желанию.
8. Сохраните задачу и проверьте её кнопкой **«Выполнить»**, затем посмотрите
   результат в `door_task.log` и на вкладке **«Журнал»** (или «История»).

## Проверка результата {#devices-scheduler-check}

- **Файл журнала**: `modules/devices/door_task.log` — сюда попадает весь вывод
  задачи (кодировка `cp1251`, открывается «Блокнотом»);
- **Планировщик**: колонка «Результат последнего запуска» (`0x0` — успех);
- **Лог приложения**: `application/logs/<год>/<месяц>/<день>.php` — задача пишет
  туда запись NOTICE с командой, количеством точек прохода и списком `ID_DEV`;
- **Состояние точек прохода** можно посмотреть на странице
  [«Группы точек прохода»](groups) или в разделе «Контроллеры».

## Меры предосторожности {#devices-scheduler-safety}

- Сначала всегда `--test=1`, потом реальный запуск вручную, и только затем —
  расписание.
- Не создавайте две задачи, которые могут сработать одновременно с
  противоположными режимами (например, «открыть навсегда» и «закрыть навсегда»
  в одну минуту).
- Для команд-режимов (`lockdoor`, `opendooralways`) обязательно предусмотрите
  обратную команду.
- Проверяйте код возврата: при `1` команда не выполнена (чаще всего — недоступен
  ТС-сервер), и в логе будет причина.
- Не запускайте задачу от имени `SYSTEM` и других учётных записей, если
  подключение к базе СКУД (`DSN ilove`) определено как пользовательское — под
  другой учётной записью задача либо не подключится, либо подключится к другой
  базе.
